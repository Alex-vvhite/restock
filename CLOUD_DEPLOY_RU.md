# Подготовка к размещению на Railway

Сервер поддерживает два режима хранения:

- без `DATABASE_URL` локально используется `server/data/state.json`;
- с `DATABASE_URL` приложение подключается к PostgreSQL и создаёт нужные таблицы.

Оба Android- и iPhone-клиента продолжают использовать один API и один набор данных. Маршруты API сохранены.

## Важно перед первым облачным запуском

Не запускайте API с пустой базой до переноса текущего `state.json`: база будет доступна, но список товаров будет пуст. Импорт скрипт выполняет только в пустую базу и записывает отметку, чтобы случайно не импортировать ту же историю повторно.

`server/data/state.json` уже исключён из Git. Он содержит текущие остатки и журнал движений; сохраните оригинал и не добавляйте его в репозиторий. `server/data/seed.json` — стартовый каталог, а не актуальное состояние остатков.

## Подготовить репозиторий

1. Создайте приватный репозиторий GitHub.
2. Добавьте в него проект из этой папки. Корнем репозитория должна быть папка, в которой находятся `server/`, `app/` и `settings.gradle.kts`.
3. Перед отправкой убедитесь, что Git исключает `server/data/state.json`, `local.properties`, `.env*`, `node_modules/` и `**/build/`. Не добавляйте пароли, строки подключения или дамп базы.
4. Если репозиторий содержит весь Android-проект, в Railway для Node.js сервиса задайте корневую папку `server`.

## Создать ресурсы Railway

1. Создайте Railway Project и добавьте сервис PostgreSQL.
2. Добавьте сервис приложения из приватного GitHub-репозитория. В настройках укажите корневую папку `server`; команда запуска берётся из `npm start`.
3. В Variables сервиса приложения добавьте `DATABASE_URL` как ссылку на переменную `DATABASE_URL` сервиса PostgreSQL, `NODE_ENV=production` и `APP_USERS_JSON` с отдельными пользователями и сильными паролями. Не вставляйте значения секретов в GitHub.
4. Не запускайте сервис приложения до импорта данных. Сначала Railway PostgreSQL должен быть пустым.

Railway предоставляет PostgreSQL-сервису внутренний адрес для связи внутри проекта. Для однократного импорта с Mac нужен временный публичный TCP-доступ к PostgreSQL. Включите его только на время импорта, скопируйте `DATABASE_PUBLIC_URL` в локальный файл окружения, который исключён из Git, и выполните из папки `server`:

```sh
npm install
npm run import:state -- ./data/state.json
```

Команда читает `DATABASE_URL` из окружения. Используйте временное локальное значение `DATABASE_URL` с публичной строкой Railway; не вставляйте строку подключения прямо в команду или чат. После успешного импорта отключите публичный TCP-доступ и удалите временную строку подключения с Mac. Импорт переносит locations, товары с текущими остатками и всю историю движений. При непустой базе скрипт откажется работать.

После импорта запустите сервис API. В Settings → Networking сгенерируйте публичный домен Railway. Проверьте `https://<домен>/api/health` — должен вернуться JSON с `ok: true` и `storage: "postgres"`.

## После запуска

- Замените в Android-клиенте локальный адрес сервера на HTTPS-домен Railway. Для iPhone используйте тот же адрес.
- Проверьте вход, просмотр остатков, запись тестового поступления/списания и появление движения в истории.
- Настройте резервное копирование PostgreSQL и сохраните отдельно исходный `state.json`.
- Не запускайте несколько реплик API, пока сессии пользователей не будут вынесены из памяти процесса.

## Локальная разработка

Без `DATABASE_URL` сервер работает через JSON-хранилище, как раньше:

```sh
cd server
npm install
npm start
```

## Реализация PostgreSQL

- `server/storage.mjs` содержит локальное и PostgreSQL-хранилища.
- `server/import-state.mjs` — однократный перенос JSON в пустую базу.
- `server/index.mjs` сохраняет прежние HTTP-маршруты и выбирает хранилище по наличию `DATABASE_URL`.
